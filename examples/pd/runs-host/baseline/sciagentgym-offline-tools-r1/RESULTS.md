## 两个明确的真实慢计算候选

### Case 25：`evolve_spin_state`

上游脚本：`toolkits/physics/atomic_and_molecular_physics/quantum_spin_dynamics_toolkit_claude_234.py`。

原生 demo 的第一个数值演化调用三次分别 **12.268 / 12.105 / 12.267 秒**，平均 **12.213 秒**。
对应电子在缓慢旋转磁场中演化，直接调用 SciPy `solve_ivp`（RK45，rtol=1e-8，atol=1e-10）。
保留上游 `B0=1 T`、`theta=pi/6`、`omega_rot=0.01*omega_0`、
`t_span=[0,100/omega_rot]`、`n_points=2000`，没有通过放大问题制造延迟。

**同一个函数在其他两个原生场景只需约 0.05 / 0.13–0.17 秒**。
因此不能把函数名绑定成固定 12 秒延迟，工具耗时依赖实际参数。

### Case 36：`analyze_bandwidth_scaling`

上游脚本：`toolkits/statistics/statistical_analysis/manifold_spectral_convergence_toolkit_claude_7.py`。

三次分别 **4.003 / 3.949 / 3.974 秒**，平均 **3.976 秒**。
原生参数包含 `n_values=[100,200,500,1000,2000]`，执行不同样本规模下的谱计算分析；
并非网络等待或图像编码占用的四秒。

其余略慢的典型调用属于绘图，例如 case 35 的 `visualize_eif_distribution` 约 1.36–1.44 秒。

## 测量口径与下一步

- 单次工具耗时不含模块加载；模块加载单独记录，约 0.18–1.39 秒。
- 只计 schema 声明工具的最外层调用，嵌套调用不重复计数；完整 demo 时间包含工具时间，二者不能相加。
- 正常返回不等于科学答案正确，本轮没有执行官方 accuracy grader。
- 临时生成的图像及中间文件在每个案例结束后清理，只保留日志、计时、源代码哈希；没有遗留实验子进程。
- 所有步骤离线 CPU 执行，无 GPU serving 服务，不能从本轮推算模型吞吐、平均轮次或 KV 使用率。

**结论：离线科学工具路线可以跑通，也确实存在原生参数下约 4 秒和 12 秒的真实计算；
但本次子集大多数调用非常快。** 值得先把 case 25/36 的原始任务与工具接入本地模型做小规模验证，
复用上游 schema、loader 和 `MinimalSciEnv`/`GenericFunctionTool`，检查模型是否自然调用慢计算。
不应强迫模型调用特定函数、伪造时间或把当前 demo 的 1.24% 直接当成未来 Agent 的 Slow 比例。
